## How It Works

Messages are keyed by ticker symbol. Kafka's default murmur2 partitioner computes:

```
partition = hash(ticker_bytes) % num_partitions
```

Same ticker always maps to the same partition, guaranteeing ordering per ticker.

## Why This Matters

1. **Ordering guarantee** — All AAPL trades arrive in order within their partition. Critical for VWAP: trade A at $210.00 must be processed before trade B at $210.05.
2. **Parallelism** — Spark reads each partition with a separate task. 3 partitions = up to 3x throughput.
3. **Even distribution** — 25 tickers across 3 partitions gives roughly 8–9 tickers per partition. No hot partition.
4. **Consumer groups** — Multiple consumers (streaming + batch reconciliation) can read independently without interference.
